🎯 How Siemens S7 addressing works

Bit: I0.0 is bit 0 of input byte 0; I1.7 is bit 7 of input byte 1.

Byte: IB0 contains I0.0–I0.7 (8 bits).

Word: IW0 contains IB0 and IB1. IW2 contains IB2 and IB3. Each uses 16 bits, and the address number is the starting byte address.

Double word: ID0 contains IB0, IB1, IB2 and IB3 (32 bits).

Byte order: Siemens S7 normally uses big-endian ordering for these multi-byte values. The earliest byte is the most significant: IW0 = IB0 × 256 + IB1.

Try it: With all other bits off, I0.0 = 1 produces IW0 = 256, whereas I1.0 = 1 produces IW0 = 1. Thus, I0.0 is bit 8 of IW0, not bit 0.

Note about overlap: IW1 is a valid Siemens address: it uses IB1 and IB2 and overlaps both IW0 and IW2. This simulator shows IW0 and IW2 because they are consecutive non-overlapping words.

📊 Data types and PLC memory areas

  • BOOL: 1 bit, TRUE/FALSE.
  • BYTE: 8 bits, unsigned 0–255.
  • WORD / INT: The same 16 stored bits; WORD treats them as unsigned, INT as signed two's-complement.
  • DWORD / DINT / REAL: The same 32 stored bits, interpreted as unsigned integer, signed integer or floating point respectively.

I and Q represent the input/output process images; M is marker memory. On real hardware, physical inputs normally update the I process image and the program controls the Q process image. Clicking bits here is an educational override, not a model of the PLC scan cycle.

REAL is not the same as an analogue input value: S7 analogue modules often supply raw INT values that must be scaled; reading their input bytes as REAL does not automatically convert them to engineering units.
